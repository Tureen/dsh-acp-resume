# 编写工作区团队文件

在工作区根的 `.agents/acp-team.yml` 定义蓝图。插件从调用会话工作目录依次找本级、父级、祖父级。文件里的 roles 是数组；profile 主插件里的 roles 是布尔值。工作区文件以映射开头，结构与 profile 的顶层 Loader 行列表不同。可复制随包的[工作区示例](../../../docs/acp-team.example.yml)。

## 定义一个角色

顶层只接受 version、roles、templates。version 可省；填写时必须是数字 1。两个列表省略时为空。解析器拒绝拼错的键。

| 蓝图键 | 作用 |
|---|---|
| name | 必填，1–32 个 Unicode 字母、数字、下划线或连字符，列表内唯一。 |
| backend | 可选。指定则首次供给按该后端；省略走新建默认路由。 |
| cwd | 可选。相对路径从团队文件所属工作区根解析；默认工作区根。 |
| summary | 给调度者和队友看的一句话，连续空白会折叠。acp_team_list 用它说明分工。 |
| seeding | 给角色自己的首次指令。有内容才额外发送播种轮，并前置角色名、队友及摘要。省略或纯空白直接处理首项任务。 |

同一工作区共享蓝图；每个 DSH 主会话有独立的花名册，记录角色对应的 chatId。修改蓝图后要让某个既有绑定采用新配置，可以按 role 关闭并解除绑定，下次派工重新供给。按 chatId 释放只关进程，后续仍可恢复。角色不能彼此直接交谈，跨角色发现由调度者转发。

### 面板上能看到团队里谁在做什么

本会话已入花名册的角色会自动出现在右侧栏 **ACP 会话 → 团队派工** 区块（无需额外配置、不新增文件或轮询），按「进行中 → 出错 → 已取消 → 已完成 → 等待派工」排序展示每张角色卡的最新任务与回执摘要，点击整卡直达该角色的详情页签，释放或删除在卡片右上角 `⋯` 菜单操作；已归入团队的角色不会在下方「其他活跃会话」或「已释放」中重复出现。

## 定义模板

templates 中每项需要唯一的非空 name、非空 steps；description 可省（默认空串），params 可省（默认空列表）。调用 acp_workflow 时参数值可为字符串、有限数值或布尔值，名字必须与声明一一对应。

- 每个步骤要有唯一 id。参数名和步骤 id 均匹配 `[A-Za-z_][A-Za-z0-9_-]{0,63}`，同一模板二者不能重名。
- parallel 与 merge 二选一。parallel 至少一项，使用角色名或带 role 和可选 prompt 的对象；角色须已定义，同一步不得重复。成员 prompt 优先于步级 prompt，都未写时基础文本为空。
- 模板用 {参数名} 或 {前一步id} 注入内容。未引用任何前步时，自动附加紧邻前一步的结果。未知占位原样保留。一个并行成员失败会留下 error，其余可继续；该步成员全部失败时终止。
- merge.mode 为 return_to_model 时必须放最后一步。mode 为 role 时须给 merge.role，可在 merge.prompt 写汇总要求，缺省使用内置汇总规则。合并步骤顶层不能另写 prompt。
- 角色功能默认开，模板功能默认关。开启 workflow 还须开启 roles。直接调用能显示工作流进度卡；侧栏按 owner 展示运行和最近五次历史。运行结束后花名册里的角色会话仍可续聊。

看到 unknown role、invalid 或 pass chatId instead 时，先从调用会话的实际工作目录找文件，再查名字及所属主会话。详见[排错](troubleshooting.md)。
